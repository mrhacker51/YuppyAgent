# YuppyCode / Jarvis Desktop (Tauri 2 shell)

Native Linux desktop window around the existing Next.js command centre
(`ui/`) and the existing Rust backend (`yuppy bridge` sidecar). The backend,
the Claude/Codex CLI adapters and the orchestrator are **not** moved or
rewritten — see `docs/DESKTOP_APP_PLAN.md` for the architecture report.

```
┌──────────────────────────── desktop (Tauri 2) ───────────────────────────┐
│  webview: ui/ static export (Next.js, xterm.js, r3f)                     │
│      │  invoke("bridge_config")  → {url, token}  (memory only)           │
│      └── ws://127.0.0.1:<port>  (token handshake, protocol v2)           │
│  src-tauri: sidecar supervisor — spawns ONE `yuppy bridge --host         │
│  127.0.0.1 --port <p>` child with YUPPY_BRIDGE_TOKEN in its env, kills   │
│  it on exit. No shell plugin, no fs plugin, core:default capability.     │
└──────────────────────────────────────────────────────────────────────────┘
                                   │ ws
                     `yuppy bridge` (yuppycode-cli): PTYs, tasks, depts
```

## Linux system dependencies

Debian/Ubuntu (jammy verified):

```bash
sudo apt-get install --no-install-recommends \
  pkg-config libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libssl-dev \
  build-essential curl file
```

Other distributions: the same libraries under their own names —
`webkit2gtk-4.1` (GTK3, libsoup3), `gtk3`, `librsvg`, `openssl`; e.g. Fedora:
`webkit2gtk4.1-devel gtk3-devel librsvg2-devel openssl-devel`; Arch:
`webkit2gtk-4.1 gtk3`. Note: Ubuntu 22.04 (jammy) ships webkit2gtk 4.1 —
Tauri 2 requires exactly the 4.1 API, not 4.0.

If port 80 is firewalled (apt defaults to http), switch
`/etc/apt/sources.list` to `https://archive.ubuntu.com/...` (backup kept at
`/etc/apt/sources.list.bak-yuppy` on the dev machine).

## Development

```bash
# 1. build the backend binary the shell supervises
cargo build --release -p yuppycode-cli

# 2a. dev mode (HMR): start the frontend and the shell separately
pnpm -C ui dev                 # http://localhost:3434
cd desktop/src-tauri && cargo run

# 2b. one-shot bundle build (.deb + .AppImage)
scripts/build_bundles.sh       # backend → static UI → Tauri bundles
```

`YUPPY_BRIDGE_BIN=/path/to/yuppy` overrides which binary the shell spawns.
Without it the shell looks for `target/release/yuppy` next to the repo root.
If no binary is found, the window falls back to the manual pairing flow
(start `yuppy bridge` yourself, paste the token) — the same flow the browser
uses today.

### Build memory note

The desktop profile is tuned for the 4 GiB CI box: `lto = false`,
`codegen-units = 4`. LTO + `codegen-units = 1` OOM-kills the linker on this
machine; the shell is a thin Tauri wrapper, so the extra optimization is not
worth the swap.

## Terminal dock controls

The dock hosts real PTYs (nothing is simulated) and is fully pointer-driven:

| Action | How |
| --- | --- |
| Resize | Drag the dock's top edge or the header grip; focus the splitter and press ↑/↓; double-click resets the default height |
| Maximize | Header maximize button — the dock fills the main content area (side panels and activity log step aside) |
| Restore | Header restore button (the same control) |
| Hide | Header chevron — collapses to a strip with a `Show dock` button; PTYs keep running |

Height, hidden and maximized state are persisted twice: immediately in
`localStorage` (`yuppy.dock.v1`, works offline) and through the bridge
`layout_save` / `layout_applied` flow under the reserved floating-panel id
`terminal-dock`. `width` is the neutral value `1` so the backend geometry
validator stays happy; `visible`/`pinned` carry hidden/maximized. Older
bridges without the entry leave the locally remembered dock untouched.

## Security model

- The webview gets `core:default` capabilities only — no shell, no
  filesystem, no http plugins.
- The sidecar argv is a fixed set (`bridge --host 127.0.0.1 --port <p>`).
  Nothing the webview sends can change the command line.
- The bridge token is generated by the shell per launch, delivered to the
  sidecar via env, and handed to the webview in memory only (never
  localStorage in desktop mode, never a URL, never logged). Browser flow
  still uses its own localStorage pairing.
- CSP allows `connect-src ws://127.0.0.1:*` for the bridge; everything else
  is `'self'`.
- The child is killed on `RunEvent::Exit` and by `Drop`.

### Export hydration

The production export prerenders the shell deterministically: the seed log
entry carries `ts: 0` (rendered as `boot`) and the matrix density starts at
2 columns. Persisted presentation (matrix columns, dock state) is applied
after hydration through `AppShell.hydratePreferences`, so the exported HTML
and the first client render never disagree (previously a wall-clock
timestamp mismatch triggered React #418).

### Bundles

| Bundle | Path | Notes |
| --- | --- | --- |
| `.deb` | `desktop/src-tauri/target/release/bundle/deb/YuppyCode_*.deb` | `dpkg -i`, depends on the GTK/webkit system libs |
| `.AppImage` | `desktop/src-tauri/target/release/bundle/appimage/YuppyCode_*.AppImage` | `chmod +x` and run; needs FUSE2 or `APPIMAGE_EXTRACT_AND_RUN=1` |

Both bundles embed the `yuppy` sidecar as `usr/bin/yuppy` next to the desktop
binary, so the shell finds it without a `YUPPY_BRIDGE_BIN` override.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Window opens, "Bridge offline" | no `yuppy` binary found → `cargo build --release -p yuppycode-cli`, or set `YUPPY_BRIDGE_BIN`; the UI also offers manual token pairing |
| `failed to open icon icons/icon.png` | run from `desktop/src-tauri` (icons ship with the crate) |
| Port race on bind | the shell picks a free port via `:0`; if the OS reuses it, the bridge errors and the UI reports it — retry |
| `pkg-config: not found` during build | Linux deps section above was skipped |
| apt fails on port 80 | use the https sources.list variant (see above) |
| AppImage/deb bundling | `cargo tauri build` with `tauri-cli` (`cargo install tauri-cli` or `npx @tauri-apps/cli`); needs the same system libs |

## Layout of files

- `desktop/src-tauri/src/sidecar.rs` — supervised child + token; unit-tested.
- `desktop/src-tauri/src/main.rs` — Tauri builder, `bridge_config` command.
- `desktop/src-tauri/tauri.conf.json` — window, CSP, bundle targets.
- `desktop/src-tauri/capabilities/default.json` — least-privilege permissions.
- `ui/next.config.ts` — conditional static export (`NEXT_EXPORT=1`).
- `ui/src/lib/store.ts` — desktop pairing bootstrap (`__TAURI_INTERNALS__`).
